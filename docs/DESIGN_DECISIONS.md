# Design Decisions

moon-release is designed with reference to release-plz, but has made several design decisions to adapt to the MoonBit ecosystem. This document explains the differences from release-plz and the reasons behind them.

## Key Differences from release-plz

### 1. Platform Support: GitHub Only

**release-plz**: Supports GitHub, GitLab, Gitea

**moon-release**: GitHub only

**Reasons**:
- The MoonBit ecosystem is currently GitHub-centric
- mooncakes.io package hosting primarily integrates with GitHub
- Focus development resources to ensure quality
- Other platforms can be added in the future if there is demand

### 2. CHANGELOG Generation: Not Supported

**release-plz**: Automatic CHANGELOG generation using git-cliff

**moon-release**: No CHANGELOG feature

**Reasons**:
- GitHub Release notes are often sufficient
- Release notes are auto-generated from commit summaries
- Manual CHANGELOG management is more flexible
- Prioritize simplicity with minimal features

### 3. Dependency Updates: Not Supported

**release-plz**: `cargo update` option for dependency updates (lock file update)

**moon-release**: No dependency update feature

**Reasons**:
- MoonBit uses **minimal version selection** like Go
- Versions are specified directly in `moon.mod.json` (no lock file needed)
- A feature equivalent to Cargo's `cargo update` is unnecessary in MoonBit's architecture

### 4. API Compatibility Check: Built-in Implementation

**release-plz**: API breaking change detection using `cargo semver-checks`

**moon-release**: Built-in API compatibility check with `semver_check` option

**How it works**:
- Uses `package_data.json` generated by `moon doc`
- Compares API between latest tag and current code
- Detects the following breaking changes:
  - Removal of pub types/functions/methods
  - Signature changes
  - Struct field removal/changes

**Detectable changes**:
| Change Type | Detection | Impact |
|-------------|-----------|--------|
| Removal of pub function | ✅ | Breaking |
| Removal of pub type | ✅ | Breaking |
| Function signature change | ✅ | Breaking |
| Struct field removal/change | ✅ | Breaking |
| Addition of pub function | ✅ | Minor |
| Addition of pub type | ✅ | Minor |

### 5. Configuration File Format

**release-plz**: `release-plz.toml` (TOML format)

**moon-release**: `release.json` (JSON format)

**Reasons**:
- The MoonBit ecosystem is JSON-centric (moon.mod.json, moon.pkg.json)
- JSON parser available in standard library
- Can read configuration without additional dependencies

### 6. Version Management Target

**release-plz**: Version management in `Cargo.toml`

**moon-release**: Version management in `moon.mod.json`

**Reasons**:
- MoonBit projects manage versions in `moon.mod.json`
- Adapts to structural differences from Rust projects

### 7. Package Registry

**release-plz**: Publishing to crates.io

**moon-release**: Publishing to mooncakes.io and npm

**Reasons**:
- MoonBit packages are managed on mooncakes.io
- Publishing via `moon publish` command
- npm support for JS target distribution (`moon build --target js` + `npm publish`)

## Implemented Features (Equivalent to release-plz)

The following features are implemented equivalent to release-plz:

| Feature | Description |
|---------|-------------|
| Conventional Commits parsing | feat, fix, docs, style, refactor, perf, test, build, ci, chore, revert |
| Breaking Change detection | `!` marker and `BREAKING CHANGE:` footer |
| Semantic versioning | Automatic major/minor/patch determination |
| GitHub Release creation | Tag + release notes |
| Auto PR creation/update | release branch → base branch |
| `pr_draft` | Draft PR creation |
| `pr_labels` | PR label assignment |
| `pr_body` template | `{{ version }}` placeholder |
| `git_tag_enable` | Enable/disable tag creation |
| `git_release_enable` | Enable/disable GitHub Release creation |
| `git_release_draft` | Draft release creation |
| `git_tag_name` / `git_release_name` | Tag/release name template |
| `git_release_body` | Release body template (`{{ version }}`, `{{ changelog }}`) |
| `allow_dirty` | Allow uncommitted changes |
| `version_group` | Version sync in monorepo |
| `custom_major/minor_increment_regex` | Custom bump rules |
| Monorepo support | Individual package management |
| `--dry-run` | Preview mode |
| `set-version` command | Manual version setting |
| `registry_check` | Version check before publish |
| `moon_publish_frozen` | `moon publish --frozen` option |
| `semver_check` | Built-in API compatibility check |
| `npm_publish` | npm registry publishing support |
| `npm_build_command` | Custom JS build command before npm publish |

## moon-release Unique Features

Features unique to moon-release not found in release-plz:

| Feature | Description |
|---------|-------------|
| `check` command | Display current state and recommended bump |
| `init` command | Initialize configuration file |
| `--prerelease` flag | Create alpha/beta/rc releases |
| mooncakes.io integration | Auto-publish via `moon publish` |
| npm registry integration | Auto-publish to npm with JS build |
| Dual publish support | Publish to both mooncakes.io and npm in one release |

## Design Principles

1. **Simplicity**: Focus on minimal necessary features, prioritize usability
2. **MoonBit Native**: Follow MoonBit ecosystem conventions
3. **GitHub-centric**: Focus on the most used platform
4. **Conventional Commits**: Adopt industry-standard commit conventions
5. **Convention over Configuration**: Minimize configuration with reasonable defaults

## Future Considerations

- GitLab / Gitea support (based on demand)
- CHANGELOG generation option (based on demand)
- Plugin system (for advanced customization)
